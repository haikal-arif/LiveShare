# Deploying FlashLive on EC2

This runs the whole stack (web app, backend, SFU, gateway and an optional TURN relay) on one EC2 instance, reachable from phones on mobile data as well as Wi-Fi. It takes about an hour the first time.

The stack is started with `docker compose`, and the `make` targets handle the `.env` file and the TLS certificate.

## 1. What you need

- An AWS account.
- A free DuckDNS subdomain, such as `flashlive.duckdns.org`.
- An email address, for the Let's Encrypt certificate.
- This project folder (`capstone_v2`) on your laptop.

## 2. Create the instance

1. **Launch an EC2 instance** in the EC2 console.
   - AMI: **Ubuntu Server 24.04 LTS**.
   - Type: **t3.medium** (2 vCPU, 4 GB). The images are built on the instance, and the Rust and Go builds need the memory. A `t3.micro` or `t2.micro` will run out of memory.
   - Storage: **30 GB** gp3.
   - Key pair: create one and keep the `.pem` file.
2. **Allocate an Elastic IP** (EC2 → Elastic IPs → Allocate) and associate it with the instance. The address then stays the same across restarts. It's free while attached to a running instance.
3. **Security group.** Use the table below for the inbound rules. Anything not listed is closed.

| Port        | Protocol    | Source    | Purpose                                    |
| ----------- | ----------- | --------- | ------------------------------------------ |
| 22          | TCP         | Your IP   | SSH                                        |
| 80          | TCP         | 0.0.0.0/0 | Let's Encrypt validation and HTTP redirect |
| 443         | TCP         | 0.0.0.0/0 | Web app, API and signaling (`wss`)         |
| 3478        | TCP and UDP | 0.0.0.0/0 | TURN                                       |
| 5349        | TCP         | 0.0.0.0/0 | TURN over TLS                              |
| 49152–49200 | UDP         | 0.0.0.0/0 | TURN relay media                           |
| 50000–50199 | UDP         | 0.0.0.0/0 | SFU media (WebRTC)                         |

Don't open 8080, 9000 or 5173. Those services are internal to Docker, and the gateway is the only way in.

Each TURN relay and each SFU connection uses its own UDP port, so the two ranges need to stay open to all clients.

## 3. Get a DuckDNS name

1. Go to [duckdns.org](https://www.duckdns.org) and sign in with GitHub, Google or Reddit.
2. Under **domains**, add a subdomain such as `flashlive`, and set its IP to the **Elastic IP** from step 2.
3. Check that it resolves from your laptop:
   ```bash
   dig +short flashlive.duckdns.org
   ```
   It should print the Elastic IP. Wait a few minutes if it doesn't.

## 4. Install the tools on the instance

Connect over SSH (replace the key file and address):

```bash
ssh -i ~/keys/flashlive.pem ubuntu@<ELASTIC_IP>
```

Then install Docker, `make`, `certbot` and the basics:

```bash
sudo apt-get update
sudo apt-get install -y make curl openssl certbot rsync
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"
newgrp docker            # or log out and back in
docker compose version   # should print a v2 version
```

## 5. Copy the project

From your laptop, copy the folder. Leave out your local `.env`, the certificates and the build folders, since the server makes its own:

```bash
rsync -av -e "ssh -i ~/keys/flashlive.pem" \
  --exclude .env --exclude 'gateway/certs/*' \
  --exclude node_modules --exclude target --exclude .git \
  --exclude 'capstone_fe/build' --exclude '.svelte-kit' \
  ~/Documents/SeaLabsBootcamp/capstone_v2/ ubuntu@<ELASTIC_IP>:~/capstone/
```

Then on the instance:

```bash
cd ~/capstone
```

## 6. Configure and start

Set up `.env` for this server. The options update `.env`; anything you leave out keeps its current value:

```bash
make docker-setup EC2=1 DOMAIN=flashlive.duckdns.org HTTPS_PORT=443 HTTP_PORT=80 TURN=1
```

- `EC2=1` reads the public IP from the instance metadata, so you don't type it.
- `DOMAIN` is the DuckDNS name. It's used in the links and the certificate.
- `HTTPS_PORT=443` and `HTTP_PORT=80` are the standard ports, so people don't need to type a port.
- `TURN=1` starts the TURN relay. Use `TURN=0` to turn it off.

Then set the **room passcode**, and optionally a participant limit, in `.env`:

```bash
nano .env
```

- `APP_ROOM_PASSCODE`: the passcode anyone must enter to create a room. Don't leave it as `changeme`.
- `APP_MAX_PARTICIPANTS`: the most people per room (sharers and watchers together). `0` means no limit.

The JWT secret and the TURN password were generated by `make docker-setup`. Don't share `.env`.

## 7. Get the certificate

Let's Encrypt gives the gateway a certificate that phones and browsers trust, so there's no warning page:

```bash
make tls DOMAIN=flashlive.duckdns.org EMAIL=you@example.com
```

This needs port 80 open (step 2) and the DuckDNS name resolving to the instance (step 3). It stops the gateway briefly while it validates, then starts it again with the new certificate.

Certificates expire after about 90 days. Run the same command again before that. It's safe to re-run at any time.

## 8. Start the stack

```bash
make docker-up
```

This builds the images and starts everything, including the TURN relay when `TURN=1` is set. The last lines show the address, and whether TURN is running.

Check that the services are up:

```bash
docker compose ps
docker compose logs --tail=50 sfu be turn
```

Open **https://flashlive.duckdns.org** in a browser. It should load with no warning.

## 9. Test it

1. **Laptop:** open the site, create a room with your passcode, and note the room code or QR code.
2. **Phone on mobile data** (turn Wi-Fi off): open the same address, join the room as a sharer, and check that the video shows up on the laptop.
3. **A second phone or laptop:** join as a watcher.
4. Check the participant limit: with `APP_MAX_PARTICIPANTS=2`, a third join should be refused with `room is full`.

If the video doesn't come through on mobile data, check the TURN logs (`docker compose logs turn`). Clients will connect through the relay when direct UDP is blocked.

## Day-to-day commands

| Task                         | Command                                                         |
| ---------------------------- | --------------------------------------------------------------- |
| Follow the logs              | `make docker-logs`                                              |
| Stop everything              | `make docker-down`                                              |
| Start again after a reboot   | `make docker-up` (the containers also restart automatically)    |
| Change the passcode or limit | Edit `.env`, then `make docker-up`                              |
| Turn TURN on or off          | `make docker-setup TURN=1` (or `TURN=0`), then `make docker-up` |
| Renew the certificate        | `make tls DOMAIN=flashlive.duckdns.org EMAIL=you@example.com`   |
| Deploy a new version         | Copy the folder again (step 5), then `make docker-up`           |

Rooms and the blocklist live in memory, so they reset when the backend restarts.

## Troubleshooting

| Symptom                                                | Likely cause and fix                                                                                                                    |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| `make tls` fails: connection refused or timeout        | Port 80 isn't open in the security group, or DuckDNS doesn't point at the Elastic IP yet. Check with `dig +short <domain>`.             |
| The site loads but shows a certificate warning         | `make tls` hasn't been run, or it failed. The self-signed certificate is the fallback.                                                  |
| The page loads, but no video shows on mobile data      | TURN isn't reachable. Check ports 3478 (TCP and UDP), 5349 and 49152–49200 (UDP) in the security group, and `make docker-setup TURN=1`. |
| Video works on Wi-Fi but not on mobile data            | UDP 50000–50199 is blocked, or TURN is off. Turn TURN on (`TURN=1`) and check the TURN logs.                                            |
| `room is full` for a join                              | `APP_MAX_PARTICIPANTS` has been reached. Raise it in `.env` and run `make docker-up`, or set it to `0`.                                 |
| `docker-setup` fails with `EC2 metadata not reachable` | Run it on the instance, not on your laptop. Or pass `HOST_IP=<public ip>` instead of `EC2=1`.                                           |
| Build fails with out-of-memory                         | The instance is too small. Use t3.medium or larger.                                                                                     |

## Security notes

- **Change the passcode** from `changeme` before you share the address.
- **TURN uses one shared username and password**, which the browser gets with the room data. That's fine for a demo. To make it stricter later, the backend can generate short-lived TURN credentials per join.
- **The site uses HTTPS**, and TURN runs over TLS too. Traffic is encrypted between the browser and the server.
- **Keep SSH limited** to your own IP in the security group.
- **`.env` holds the secrets.** Don't commit it or copy it to shared places.
- **Stop the instance** when the demo is over, so you aren't billed for compute. The Elastic IP costs a little while the instance is stopped, so release it too if you won't use the server again.
