## 3. Decisions & Trade-offs

- **Ports owned by the consumer, not the implementer**: `usecase` declares `RequestClient`, `RoomStore`, `StageStore`, `StreamerStore`, `BlackListStore` and friends; `repository` and `httpclient` implement them and `main.go` is the only place that knows the concrete types. Trade-off: more small interfaces and a generated mock file, but every business rule is unit-testable without HTTP or a real SFU, and swapping the in-memory store for a database later touches one package.
- **Admin token as a stateless JWT instead of a stored key**: nothing to look up or clean up when a room closes, and a token for a closed room stops working because `room_id` no longer matches. Trade-off: tokens never expire while the room is open (no `exp`) and can't be revoked individually. Accepted for a one-room local app.
- **Blacklist by IP, resolved at block time**: the admin only ever sees `peer_id`, so Go asks the SFU for the IP once and stores that. Trade-off: everyone behind the same IP is blocked, and a client that talks to the SFU websocket directly bypasses the check, because enforcement lives in Go. Viewers can't be blocked at all since the admin never sees their `peer_id`. All three are recorded as accepted gaps.
- **Poll the SFU for liveness, only while an events stream is open**: simpler than the SFU pushing events to Go and costs nothing when nobody is watching. Trade-off: up to 2 s before a streamer shows offline on the stage (watchers still get `publisher_left` from the SFU instantly), and a new events client gets one redundant `stage_updated` from the baseline poll.
- **Dropped the rate limiter** middleware that the earlier backend plan included (commit `30420bb`). Trade-off: one less stateful component for a local-network app, but nothing slows down a client that hammers the API. Revisit if the server is ever exposed beyond the LAN.
- **Refactor SFU in small behavior-preserving steps, tests first**: ids/errors → file splits → ports → transport, one commit each, with the existing integration tests as the safety net. Trade-off: a longer commit history than one big restructure, but any step can be bisected or reverted.
- **Enforce layering in CI with a grep**: crude, but cheap and catches the exact mistake that would undo the refactor (WebRTC or HTTP types leaking into room logic). A proper crate boundary would be stronger and is a later option.
- **Typed `DomainError` with a wire `code`**: the websocket `error` message gets an additive machine-readable `code` while `reason` text is unchanged, so the frontend can switch on codes without breaking older clients.
